# Протокол сообщений

Все сообщения — через `SendMessage`. Первая строка — самодостаточная (её видно в превью). Каждое сообщение содержит всё нужное: получатель не видит разговор контроллера. Ответ — на атрибут `from` входящего `<cross-session-message>`.

Каждое сообщение контроллера начинается с тега `[ORCH]`, каждый отчёт воркера — с `[REPORT <роль> <задача>]`. Так обе стороны отличают протокол от болтовни.

## 1. Онбординг (контроллер → каждая сессия, один раз)

```
[ORCH] Ты назначен в оркестр агентов: роль {РОЛЬ}. Загрузи скил agent-orchestrator и действуй по разделу «Воркер: {РОЛЬ}».
Контроллер: эта сессия (отвечай на from этого сообщения).
Проект: {путь к основному репозиторию}
План: {путь к tasks.md / ROADMAP.md}
Базовая ветка MR: {main}
{для тестировщиков} Уровень тестирования: {L}. Скил: test-council, режим одной роли.
{для wiki} База знаний: {путь}
Правила: в main не пушить никогда; работать только в worktree, который назовёт контроллер; продакшен-код меняет только кодер.
Ответь: [REPORT {РОЛЬ} -] ready
```

Роли: `coder`, `optimist`, `realist`, `pessimist`, `wiki`.

## 2. Задача кодеру

```
[ORCH] Задача {ID}: {название} — реализуй в ветке {branch}.
Worktree: {путь} (ветка {branch} уже создана от {base})
Текст задачи:
{вывод plan.py show ID}
Уровень тестирования: {L} — новое поведение покрой общими тестами (не под задачу: по модулю и поведению).
Порядок: тест первым → правка → коммит → мутация (скил mutation-check). Каждая правка — свой мутант (код без неё), который роняет именно её тест.
Спека мутантов: {worktree}/.orchestrator/mutants-{ID}.json — контроллер перепрогонит её сам.
Когда готово: закоммить в ветку (не пушь), прогони полный набор тестов и мутации и ответь:
[REPORT coder {ID}] done
- коммиты: {git log --oneline base..HEAD}
- полный прогон: {команда} → {N passed, M failed}
- мутации: {таблица mutate.py: id | ожидаемый тест | упали | вердикт}, контроль и прогон отката
- снятые правки-пустышки: {что и чем доказано | нет}
- что сделано / решения / что осталось спорным
```

## 2b. Возврат кодеру по гейту мутаций

```
[ORCH] Задача {ID}: гейт мутаций не пройден (цикл исправлений {N}/3) — разбери непойманные мутанты в той же ветке.
Перепрогон контроллера: {таблица из mutate.py, только не-KILLED}
{правки без мутанта: файл:строки | нет}
Разбор — по скилу mutation-check: прибор → пустой мутант → слабый тест → правка-пустышка (правку снять, тест не подгонять).
Ответь: [REPORT coder {ID}] fixed + коммиты + новая таблица мутаций
```

## 3. Задача тестировщику (каждому из трёх)

```
[ORCH] Задача {ID}: протестируй ветку {branch} в роли {РОЛЬ} (test-council, режим одной роли).
Worktree: {путь}
Что тестируем: {название, критерии приёмки, отчёт кодера, git diff --stat base..HEAD}
Мутации (гейт пройден, перепрогон контроллера): {таблица}
Команда полного прогона: {команда}
Базовая линия храповика: {ratchet.py status}
Guard: {ratchet.py guard --base base}
Параллельный запуск: {да | нет — запускай полный прогон только после сообщения «твоя очередь»}
Новые тесты — только в новых файлах, не коммить (коммитит кодер после вердикта).
Ответь отчётом в формате test-council: [REPORT {РОЛЬ} {ID}] + ВЕРДИКТ/…
```

## 4. Раунд дебатов (контроллер → каждый тестировщик)

Промпт раунда из `test-council/references/roles.md` («Промпт раунда дебатов»), с префиксом:
```
[ORCH] Задача {ID}: раунд дебатов {K}/3 — ответь на аргументы двух других ролей.
```

## 5. Исправления кодеру (вердикт FAIL)

```
[ORCH] Задача {ID}: совет вынес FAIL (цикл исправлений {N}/3) — исправь в той же ветке.
Проблемы (по отчётам совета):
- [критично] … — как воспроизвести — кто нашёл
Новые тесты совета, которые падают (не правь и не удаляй их — чини код):
- {файл::тест}
Новые правки докажи мутациями (дополни спеку {worktree}/.orchestrator/mutants-{ID}.json) — контроллер перепрогонит её до совета.
Ответь: [REPORT coder {ID}] fixed + коммиты + полный прогон + таблица мутаций
```

## 6. Финализация кодеру (вердикт PASS)

```
[ORCH] Задача {ID}: совет вынес PASS — закоммить тесты совета и открой MR.
1. git add новых тестов совета и .test-ratchet.json (контроллер уже выполнил ratchet update); отметь задачу в плане: plan.py set {ID} review; коммит «test({ID}): tests from test council».
2. git push -u origin {branch}   (НЕ main — хук всё равно не пустит)
3. MR: {gh pr create --base main --head {branch} --title "{ID}: {название}" --body-file - | glab mr create --target-branch main --source-branch {branch} --title "{ID}: {название}" --description "…"}
   Тело MR — шаблон ниже.
Ответь: [REPORT coder {ID}] mr {ссылка}
```

Шаблон тела MR:
```
## {ID}: {название}

{описание задачи, 2–3 предложения}

### Критерии приёмки
- [x] …

### Совет тестирования — PASS ({консенсус в раунде K | решение человека})
| Роль | Вердикт | Главный аргумент |
|---|---|---|
| Оптимист | PASS | … |
| Реалист | PASS | … |
| Пессимист | PASS | … |

Тестов: N (+M новых) · Покрытие: C% · Уровень: L

### Мутации — каждая правка доказана
| id | правка | ожидаемый тест | вердикт |
|---|---|---|---|
| … | … | … | KILLED |

Контроль на чистом коде и прогон после отката — зелёные; свежий PYTHONPYCACHEPREFIX на каждый прогон. Снятые правки-пустышки: {… | нет}

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

## 7. Пополнение базы знаний (контроллер → wiki)

```
[ORCH] Задача {ID}: MR открыт — добавь отчёт по задаче в базу знаний {путь} (ingest).
Источник (сохрани в raw/ как {дата}-{branch}.md и проведи полный ingest по скилу llm-wiki):
---
url: {ссылка на MR}
---
# {ID}: {название}
## Что сделано
## Решения и причины
## Найденные проблемы и как их решили
## Итог тестирования (вердикт, ключевые аргументы ролей, новые тесты)
## Мутации (какие правки доказаны, что выжило и как разобрано, снятые правки-пустышки)
## Открытые вопросы
Ответь: [REPORT wiki {ID}] done + созданные/обновлённые страницы
```

## Отчёты-исключения от любого воркера

```
[REPORT {роль} {ID}] blocked — {что мешает, что нужно от контроллера/человека}
```
Контроллер не «додумывает» ответ за воркера: нет отчёта — ждёт; заблокирован — решает сам, если это в его полномочиях, иначе спрашивает человека.
