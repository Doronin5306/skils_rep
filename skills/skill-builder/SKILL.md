# Skill Builder

Создаёт скилы в репозитории `/Users/b2b-connect/Doronin/skils_rep` и подключает их к Claude Code.

## Устройство репозитория

```
skils_rep/
├── README.md              # каталог скилов (таблица генерируется автоматически)
├── install.sh             # симлинки skills/* → ~/.claude/skills/
└── skills/
    └── <skill-name>/
        ├── SKILL.md       # обязательно: frontmatter + инструкции
        ├── references/    # справка, которую Claude читает по необходимости
        ├── scripts/       # исполняемый код для детерминированных шагов
        └── assets/        # шаблоны и файлы, которые идут в результат
```

Скилы устанавливаются **симлинками**, поэтому правки в репозитории сразу видны Claude Code — переустанавливать не нужно.

Пути ниже даны относительно корня репозитория; `SB=skills/skill-builder/scripts`.

## Процесс

### 1. Понять задачу

Сначала извлеки всё, что можно, из текущего разговора: какие шаги делались, какие инструменты, какие исправления вносил пользователь, какой формат результата. Спрашивай только то, чего не хватает. Нужно знать:

- **Что делает скил** — одна фраза.
- **Когда срабатывает** — 3–5 реальных формулировок запросов пользователя (включая неявные, где слово «скил» не звучит).
- **Вход и выход** — что пользователь даёт и что получает (файл, ответ, коммит, артефакт…).
- **Что нестабильно без скила** — где Claude ошибается или каждый раз изобретает заново. Именно это и надо зафиксировать в скиле.

Если скил — это сохранение чего-то уже сделанного в разговоре, не задавай вопросов, на которые разговор уже ответил.

### 2. Выбрать имя

kebab-case, латиница, ≤ 64 символа, описывает действие или предмет: `pdf-report`, `deploy-staging`, `review-sql`. Проверь, что такого скила ещё нет:

```bash
ls skills/
```

Если похожий скил уже есть — предложи доработать его вместо создания нового.

### 3. Создать каркас

```bash
python3 $SB/init_skill.py <skill-name> [--with references,scripts,assets]
```

Создаёт `skills/<skill-name>/SKILL.md` из шаблона. Подпапки добавляй только если они реально нужны.

### 4. Написать `description` — самое важное

Description — единственное, что Claude видит до загрузки скила; по нему решается, сработает ли скил. Правила:

- Сначала **что делает**, затем **когда использовать** («Используй, когда…»).
- Перечисли конкретные триггеры: формулировки, типы файлов, названия инструментов, контексты. Добавь английские синонимы — пользователь может писать на любом языке.
- Будь чуть «настойчивее», чем кажется нужным: Claude склонен недоиспользовать скилы.
- Если есть соседние скилы с похожей областью — укажи, когда этот **не** использовать.
- Без угловых скобок `< >`, ≤ 1024 символа.

### 5. Написать тело SKILL.md

- **Повелительное наклонение**, коротко. Claude и так умный — пиши только то, чего он не знает: специфику пользователя, проекта, порядок шагов, подводные камни.
- **Объясняй «почему»**, а не кричи MUST/НИКОГДА. Понимая причину, модель правильно обобщает на новые случаи.
- **Конкретика**: точные команды, пути, форматы вывода, пример хорошего результата.
- **< 500 строк.** Длинная справка → `references/*.md` со ссылкой из SKILL.md и пояснением, *когда* её читать.
- **Повторяемый код → `scripts/`.** Если Claude каждый раз пишет один и тот же скрипт — положи его в скил. Скрипты должны работать без интерактивного ввода и печатать понятные ошибки.
- Не дублируй информацию между SKILL.md и references.

Подробные паттерны, поля frontmatter и анти-паттерны — в `references/best-practices.md`. Прочитай его, если скил нетривиальный (скрипты, несколько вариантов работы, побочные эффекты) или если сомневаешься в структуре.

### 6. Проверить

```bash
python3 $SB/validate_skill.py skills/<skill-name>
```

Исправь все ошибки (ERROR); предупреждения (WARN) — по ситуации.

Затем мысленно прогони 2–3 примерных запроса из шага 1: сработает ли скил по description? Хватит ли инструкций, чтобы выполнить задачу без догадок? Если скил содержит скрипты — запусти их на реальном примере.

### 7. Установить и обновить каталог

```bash
./install.sh <skill-name>
python3 $SB/update_catalog.py
```

`install.sh` создаёт симлинк в `~/.claude/skills/`. `update_catalog.py` перегенерирует таблицу скилов в README.md. Скил станет доступен в **новой** сессии Claude Code.

### 8. Git

Покажи пользователю итог (дерево файлов и description) и предложи закоммитить:

```bash
git add skills/<skill-name> README.md && git commit -m "Add <skill-name> skill"
```

Коммить и пушь только с согласия пользователя.

## Доработка существующего скила

1. Прочитай текущий `SKILL.md` и всё, на что он ссылается.
2. Выясни проблему: не срабатывает (→ правь description), срабатывает не там (→ сузь description, добавь «не использовать, когда…»), делает не то (→ правь инструкции, добавь пример или скрипт).
3. Вноси минимальные изменения, сохраняя имя (`name` и папку) — на них могут ссылаться.
4. Шаги 6–8.
