# tenders-api — запись в общую БД `tenders`

HTTP-шлюз в общую PostgreSQL для всех парсеров. Репозиторий `parsers/parsers_orm` ведёт **другая сессия** — его код и схему не правим. Нужна новая platform, ключ, поле или изменение контракта → пишем промпт владельцу.

## Адреса и ключи

- Из Docker-контейнера на pp.trade.su: `http://tenders_api:8000` (контейнер в сети `--network tenders_net`).
- Из LAN (ВМ selenium, dp1/dp2): `http://192.168.0.202:8020`.
- Ключ — свой у каждого парсера, таблица `api_clients`, поле `allowed_platforms`. Запись чужой platform → 403. В `.env` на машине парсера, никогда в git. Ключ utp_sberbank, например, лежит на pp.trade.su в `/opt/tenders_api/keys/<парсер>.key` (читать через sudo).
- Если в одном репозитории два парсера — два ключа (`TENDERS_API_KEY`, `RTS_TENDERS_API_KEY` в gz_spb).
- Добавили домен/секцию → его надо дописать в `allowed_platforms` у владельца, иначе 403.

## Контракт

`POST {TENDERS_API_URL}/v1/tenders`, заголовки `Content-Type: application/json`, `X-API-Key: <ключ>` (именно `X-API-Key`, не Bearer).

```json
{
  "platform": "223.rts-tender.ru",
  "item_id": "4078398",
  "source_url": "https://.../View.aspx?Id=4078398",
  "fields": {"Подпись": "значение", "...": "..."},
  "documents": [{"name": "Извещение.pdf", "url": "https://...", "local_path": "rts/223.rts-tender.ru/2026-10-27/4078398/docs/Извещение.pdf"}],
  "scraped_at": "2026-10-30T16:20:00+00:00",
  "customer": {"company_id": "<id>", "source_url": "...", "fields": {}}
}
```

- **Upsert по `(platform, item_id)`** — повторная отправка безопасна, ответ `{"id": ...}`.
- `scraped_at` — ISO **с таймзоной**; наивная строка → 422. В Docker время UTC, на ВМ — МСК: явно делай `.replace(tzinfo=...)` / `datetime.now(timezone.utc)`.
- Символ `\x00` в строках → 422. Чистить: `re.sub(r'\s+', ' ', text.replace('\x00', '')).strip()`.
- `fields` — **сырые пары подпись → значение** со всех блоков карточки. Извлечением title / organization / ИНН / статуса / даты публикации владеет сервис. Повтор подписи с другим значением — `"Подпись (2)"`.
- Канонические поля — можно и нужно добавить, если площадка называет их иначе: `Наименование процедуры`, `Наименование организации`, `ИНН организации`, `Статус процедуры`, `Способ процедуры`, `Дата и время публикации процедуры`, `Дата публикации извещения`. Без времени публикации сервис ставит полночь МСК и процедура уезжает на прошлый день в UTC — берите время из списка, если на карточке его нет (utp_sberbank).
- `platform` — хост площадки; если у площадки секции/тенанты, которые нужно различать, — `host/секция` (utp_sberbank) или реальный домен заявки (rts_market).
- `local_path` — **относительно корня веб-архива `/archive/selenium`** и только для реально скачанных файлов: веб-интерфейс отдаёт файлы с нашего сервера. Пути разных парсеров не пересекаются за счёт первого сегмента (`utp_sberbank/files/...`, `rosatom_rts/...`, `rts_44/...`). Если ссылка площадки работает только с сессией — `url` всё равно можно передать, но файл берётся по `local_path`.
- `customer` необязателен. Если есть — `company_id` непустой (иначе 422). `{company_id}` без полей привязывает к уже известной организации, ничего не перезатирая (когда карточку заказчика открыть не удалось).

## Пачки

`POST /v1/tenders/batch`, тело `{"items": [...]}`, до `BATCH_SIZE = 50`. Ответ — список по позициям `{"ok": bool, "error": ...}`; ошибки разбирать поштучно.

## Best-effort и досылка

- Отправка не должна останавливать сбор: try/except вокруг отправки, warning в лог, карточка остаётся в архиве.
- Не настроены `TENDERS_API_URL`/ключ → один warning за прогон и работа без отправки (`is_configured()` в rosatom/rts_parser).
- Досылка — режим `--resend [--date D | --since D] [--dry-run]`: читает архив, собирает тело (`build_item(item_dir)`) и шлёт пачками. `--dry-run` печатает канонические поля, число полей и документов — так проверяют разбор перед реальной отправкой. Поэтому тело запроса строится **из файлов архива**, а не из памяти прогона: один и тот же код для сбора и для `--resend`.
- Очередь при недоступности API (utp_sberbank): после 3 неудач подряд остальное в прогоне сразу в `tenders_api_pending.json` (чтобы не ждать таймауты), досылка в конце и в следующих прогонах, старше 7 дней — выбрасывать.

## Тонкий клиент

Шаблон — `assets/tenders_api.py` (stdlib-парсер `.env` + `post()`). В проектах на pydantic-settings клиент — `db.py` с `requests.Session` и заголовком `X-API-Key` (rts_tender, rts_market, rts_selenium).
