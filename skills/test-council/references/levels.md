# Уровни тестирования

Уровень проекта хранится в `.test-ratchet.json`. Каждый уровень включает все требования предыдущих. Уровень можно только поднять (`ratchet.py raise`).

| Уровень | Название | Что обязательно |
|---|---|---|
| 1 | Smoke | Проект собирается/импортируется; весь существующий набор тестов запускается и зелёный |
| 2 | Unit | + линтер и проверка типов (если в проекте настроены); новое поведение покрыто unit-тестами |
| 3 | Integration | + интеграционные тесты на стыках модулей; граничные значения и пути ошибок для изменённого кода; покрытие измеряется и не падает |
| 4 | Adversarial | + property-based / фаззинг для функций с нетривиальным входом; невалидный и враждебный ввод; конкурентность и ресурсы (если применимо); базовые проверки безопасности (инъекции, секреты, права) |
| 5 | Full | + мутационное тестирование изменённых модулей (mutmut, Stryker, PIT, go-mutesting…) — выживших мутантов надо убить или обосновать; производительность критичных путей не деградирует |

Если инструмент уровня в проекте не установлен (например, нет mutation-тестера на уровне 5) — агент ставит его локально, если это возможно без изменения зависимостей проекта, иначе прямо пишет в отчёте, какое требование не проверено. Непроверенное обязательное требование — аргумент за FAIL у Пессимиста и за «неполноту» у Реалиста; молча пропускать его нельзя.

## Метрики храповика

| Метрика | Правило |
|---|---|
| `level` | не ниже базового |
| `tests` | число тестов в **полном** прогоне — не меньше базового |
| `coverage` | если базово измерялось — должно измеряться и не падать (допуск 0.01 п.п. на округление) |

Плюс `ratchet.py guard` ловит ослабления в git-изменениях: удалённые тестовые файлы, уменьшение числа тестов или assert-ов в файле, новые `skip`/`xfail`/`only`, понижение или удаление порогов покрытия в конфигах, ручную правку `.test-ratchet.json` вниз.

## Как получить число тестов и покрытие

| Стек | Полный прогон с покрытием | Где число тестов |
|---|---|---|
| Python | `pytest -q --cov --cov-report=term` | строка `N passed` |
| JS/TS (jest) | `npx jest --coverage` | `Tests: N passed` |
| JS/TS (vitest) | `npx vitest run --coverage` | `Tests N passed` |
| Go | `go test ./... -cover -json` | число событий `"Action":"pass"` с полем `Test` |
| Rust | `cargo test` (+ `cargo llvm-cov`) | `test result: ok. N passed` |
| Java | `mvn test jacoco:report` / `gradle test jacocoTestReport` | `Tests run: N` |

Если в проекте есть свой скрипт (`make test`, `npm test`) — используй его, он важнее таблицы.
